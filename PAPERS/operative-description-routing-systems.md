## 1. Introduction: The Label as Lever

Some descriptions sit on the page; other descriptions move things. A text string archived on an unread backup drive is representational; a text string parsed by an active routing engine is operational. The inquiry of this project begins at this transition: **how a label becomes a lever, how a small word moves a large system, and how philosophy of language is dragged into a workflow.**

Against the classical semantic assumption that language acts as a passive mirror of objects, this paper develops a theory of **operative description routing systems**. We study the symbolic valves—labels, prompts, scores, and schemas—that classify situations inside contemporary human-machine systems in ways that determine what happens next. In doing so, we trace a crucial media-theoretical transition: the shift from Mitchell’s static *imagetext* (words referencing images) to the computational *worldtext* (descriptions compiling navigable simulation environments).

## 3. The Epochs of Operative Language

The migration from passive naming to executable compiler occurs across five historical and conceptual epochs:

### Epoch 1: Conceptual Ignition (1950s–1970s)
*   **Locale:** Philosophy of Language and Symbolic Anthropology.
*   **Sources:** Wittgenstein (*Philosophical Investigations*), Austin (*How to Do Things with Words*), Geertz (*The Interpretation of Cultures*), Grice (*Logic and Conversation*).
*   **Dominant Question:** How does language act? How does description depend on social context?
*   **Tension:** Language as representation vs. language as use; thin description vs. thick description.

### Epoch 2: The Infrastructural Turn (1980s–1990s)
*   **Locale:** STS, CSCW, and Classification Studies.
*   **Sources:** Bowker and Star (*Sorting Things Out*), Star and Ruhleder (*Steps Toward an Ecology of Infrastructure*), Suchman (*Plans and Situated Actions*), Hutchins (*Cognition in the Wild*).
*   **Dominant Question:** How do categories organize labor? How do artifacts distribute cognition?
*   **Tension:** Rigid taxonomy vs. situated practice; individual cognition vs. distributed environments.

### Epoch 3: The Platform Governance Turn (2010s)
*   **Locale:** Platform Studies and Trust & Safety Research.
*   **Sources:** Gillespie (*Custodians of the Internet*), Roberts (*Behind the Screen*).
*   **Dominant Question:** How does speech become governable? How do moderation labels route visibility?
*   **Tension:** Platform circulation vs. speech suppression; automated metric judgment vs. cultural context.

### Epoch 4: The AI-Agent Turn (2020s)
*   **Locale:** Large Language Models, Tool-Use Environments, and Prompt Engineering.
*   **Sources:** OpenAI Function-Calling Schemas, Agentic Workflow Frameworks.
*   **Dominant Question:** How do tool descriptions condition model action? What happens when the same tool receives different descriptions?
*   **Tension:** Natural language as representational description vs. natural language as executable compiler condition; tool availability vs. tool selection.

### Epoch 5: Proposal Discipline (2026)
*   **Locale:** Advisor Scoping and Committee Defense.
*   **Sources:** Scope audits, case-feasibility rubrics, and counterfactual design.
*   **Dominant Question:** What is the primary case? What would disprove the claim?
*   **Tension:** Metaphysical ambition vs. empirical feasibility; conceptual atmosphere vs. causal proof.

## 4. The Conceptual Migration Map

This project executes a series of deliberate intellectual migrations to move the study of language away from decorative abstraction:

1.  **From Philosophy of Language to Infrastructure:** Meaning-as-use requires a material system where use is observed. We migrate from asking what language *means* to tracing what descriptions *route*.
2.  **From Symbolic Anthropology to Classification Studies:** Thick description explains cultural significance but lacks institutional teeth. We migrate from tracking cultural significance to mapping category-backed action.
3.  **From Speech-Act Theory to Operative Description:** Austin's explicit performatives ("I promise") do not cover descriptive labels embedded in software loops. We migrate from the isolated *speech act* to the structural *system act*.
4.  **From Platform Governance to AI-Agent Tool Use:** Comment moderation makes routing visible, but LLM tool descriptions make causality experimentally testable. We migrate from governance analysis to variable-controlled API testing.
5.  **From Grand Cybernetic Theory to the Description/Action Pair:** Universal feedback systems risk becoming vague metaphors. We migrate from total operator metaphysics to the **description/action pair** as our stable unit of analysis.
6.  **From Case Constellations to Primary-Case Hierarchy:** Rather than chasing three massive cases simultaneously, we establish a hierarchy: LLM tool descriptions are the primary experimental core; GitHub labels serve as the comparative labor case; toxicity moderation serves as the political governance context.

## 5. Case 1: Prompting as Operative Ekphrasis (Imagetext)

The ancient definition of **ekphrasis** was operative: it referred to verbal descriptions that produced vivid, visual experiences within the listener (*enargeia*), rather than merely describing pre-existing images. The mid-twentieth-century redefinition (Spitzer, 1955) narrowed ekphrasis to the "verbal representation of visual representation," separating word from image. 

Generative AI diffusion models restore the ancient operation computationally. A text prompt is not a description of an existing image; it is the **executable control signal** that steers the sampling pathway in latent vector space. The description and the generation collapse into a single act:
*   **The Compiler in Latent Space:** Natural language functions as a visual compiler.
*   **Latent Viscosity:** The prompt operates against the model's pre-trained training distribution, which exerts a statistical gravity. The prompter's creative will engages in "latent bricolage" to steer the system away from default platform means into precise visual valleys.

## 6. Case 2: Thick Prompting and Context Engineering

Clifford Geertz’s (1973) thick description established that meaning is not "more detail," but selected context that alters the identity of an act (e.g., distinguishing a blink from a wink). In generative AI, thin prompting suffers from **latent drift**—the model’s default training distribution overrides thin instructions, causing the environment to collapse into generic defaults.

To prevent this, we formalize **Thick Prompting** as a context-engineering architecture mapped directly onto Geertz's six layers of thick description:

| Layer | Geertzian Thick Description | The Thick Prompt (Context Stack) |
| :--- | :--- | :--- |
| **1. Visible Act** | What physically happens? | **Content Tokens:** What literal assets must be generated. |
| **2. Native Act** | What do the participants take themselves to be doing? | **Intent Embedding:** The narrative context and purpose of the output. |
| **3. Code** | What normative order makes the act intelligible? | **Style Conditioning:** The genre, visual grammar, or artistic tradition. |
| **4. Audience** | Who is watching, recognizing, or misreading? | **Evaluation Frame:** The expectations and visual literacy of the receiver. |
| **5. Stakes** | What is really at risk? | **Weight Signal:** What aspects of the output are prioritized (attention weights). |
| **6. Reclassification** | What does the same act become in another setting? | **Transfer Context:** How the output survives context-switching (durability). |

### The Warning of the Cohen Case
Geertz's Cohen sheep-theft vignette illustrates the failure of thin prompting. Cohen translates his grievance into a local code (the *mezrag* covenant), which works within its native frame (he gets the sheep). However, when the sheep cross into the French colonial jurisdiction, they are re-classified as "rebel collusion," and Cohen is imprisoned. 

This is the classic failure of thin prompting: specifying a request in only one code, failing to anticipate how it will be re-classified when transported across different evaluation contexts. A thick prompt embeds multiple context layers to ensure the output remains robust and legible under **reclassification**.

## 7. Case 3: Narrative Control in Generative Worldtexts

In modern AI architectures, the transition from image models to spatial-temporal world models (Sora, Genie, RIPPLES) shifts the output from Mitchell’s static *imagetext* to the navigable *worldtext*—a multi-layered simulation environment with its own persistent physics and behaviors. 

In this worldtext, **narrative functions as a control surface**. The context stack (L0–L6) converts language directly into space:
*   **The World Bible (L1)**: Formulates structural invariants (the laws of the simulation).
*   **The Lore Book (L2)**: Houses the subjective, often contradictory histories and rules that the model reads to generate environment details.

This execution is demonstrated at two scales:
1.  **The Shield of Achilles as Ur-Worldtext:** Homer's description of Hephaestus's forge is a programmatic compilation. The hexameter is the compiler, and the metal is the substrate. The concentric rings establish a persistent cosmology (*completeness*, *invention*, *consistency*) bounded by the River Ocean.
2.  **LLM Tool Schemas:** An LLM agent reads tool schemas (descriptions and arguments) to determine whether and how to invoke code functions. The description is not documentation; it is the executable constraint system that steers model execution.

## 8. Boundary Defense: When is a Description NOT Operative?

A description is **not** operative when its application does not alter the probability distribution of subsequent actions in a system. If the presence of description $D$ yields an action-space delta of zero ($\Delta P = 0$), it is non-operative:
*   **Non-Operative:** A description stored on a cold backup drive that is never parsed, or a label on an interface that triggers no branching logic and directs no user attention.
*   **Operative:** A label, prompt, schema, or score that is coupled to an operator and an infrastructure, acting as the valve that steers subsequent workflow.

### The Unit of Analysis
The unit of analysis is the **description/action pair**:

$$\text{Unit} = \langle D, A_{\text{route}} \rangle$$

where $D$ is the specific descriptive form (a label, prompt, or schema) and $A_{\text{route}}$ is the route it makes more likely, legitimate, or automatic.

### Causality and the Counterfactual
To prove that the description itself caused the routing, we hold the underlying input object constant and vary only the description:
*   *GitHub:* Compare resolution times and assignee behaviors for identical issues that received different labels (or no labels).
*   *Moderation:* Pass comments with identical toxicity scores through warning vs. no-warning moderation workflows.
*   *LLM Tools (The Primary Case):* Hold the model and the user prompt constant. Vary only the `description` string inside the tool's JSON schema (e.g., *"Issue refund"* vs. *"Only issue refund after verification"*), and measure the tool call rate.

## 9. The Final Checklist

1.  **What is operative description?** A symbolic classification coupled to an infrastructure that routes subsequent action.
2.  **What is not operative description?** An unread description stored in an inactive archive is not operative because its action-space delta is zero.
3.  **What is your primary case?** The primary case study is LLM tool descriptions.
4.  **What is your unit of analysis?** The unit of analysis is the description/action pair.
5.  **What route does each case show?** Prompting routes visual generation; thick prompting routes context compliance; tool schemas route machine execution.
6.  **What evidence proves routing?** System database timestamps, generator seed logs, and API call JSON records prove routing.
7.  **What is your counterfactual?** The counterfactual is the behavior of identical inputs without the label or with altered schema descriptions.
8.  **What data can you actually access?** We access open GitHub repository logs, public toxicity datasets, and developer API transaction logs.
9.  **What would disprove or weaken your claim?** If varying LLM schema descriptions fails to alter model invocation rates under identical prompts, the claim is weakened.
10. **Why is this not just speech-act theory?** Speech-act theory focuses on isolated performative utterances, whereas we focus on classifications embedded in multi-step platform workflows.
11. **Why is this not just classification?** Classification merely sorts objects into categories, whereas operative description unifies the sort with the instructions that route the operator.
12. **Who controls the descriptions?** Platform architects, software developers, and institutional administrators control the descriptions.
13. **Who can contest them?** Operators can contest descriptions through system feedback loops such as appeals, relabeling, and retry protocols.
14. **Who pays when they are wrong?** The categorized subjects (silenced users, denied customers, under-triaged patients) pay when they are wrong.
15. **Why does this matter now?** It matters now because natural language is no longer passive representation; it is directly executed as system code.
